# [플랫폼 또는 프로젝트 이름]

[프로젝트 목록](../../projects/README.md)으로 돌아갑니다.

이 폴더를 `projects/<묶음>/`으로 복사해 씁니다.
대괄호 안 안내를 실제 내용으로 바꾸고 이 안내를 지웁니다.
모르는 내용은 `확인 필요`, 관련 없는 내용은 `해당 없음`으로 적습니다.

[누가 어떤 목적으로 사용하는 플랫폼이나 프로젝트인지 한 문장으로 적습니다.]

## 기본 정보

| 항목 | 내용 |
| --- | --- |
| 프로젝트 구분 | [회사 또는 사이드] |
| 회사 설명 | [어떤 일을 하는 회사인지 한 문장. 사이드는 해당 없음] |
| 진행 방식 | [개인 또는 팀] |
| 관련 저장소 | [저장소 이름과 주소] |
| 실제 참여 기간 | [시작일 ~ 종료일 또는 확인 필요] |
| 맡은 역할 | [내가 맡은 일을 한 문장으로 요약] |
| 현재 상태 | [개발 상태와 실제 운영 상태를 짧게 구분] |
| 기록 기준일 | [YYYY-MM-DD] |

회사 이름이나 별칭, 사람 이름이나 계정 이름은 적지 않습니다.

## 작업 목록

같은 플랫폼의 업무는 이 폴더 안에 파일 하나씩 만듭니다.
`templates/task.md`를 `projects/<묶음>/<작업>.md`로 복사해 씁니다.
아래 작업 이름에 같은 폴더의 작업 파일 링크를 연결합니다.

| 작업 | 짧은 설명 | 기간 | 현재 상태 |
| --- | --- | --- | --- |
| [작업 이름과 파일 링크] | [무엇을 바꿨는지 한 문장] | [기간] | [상태] |

설명, 역할 분담, 기술, 결과, 순서도, 근거는 각 작업 파일 한 곳에 적습니다.
작성 기준은 [작성 방법](../../writing-guide.md)을 참고합니다.
