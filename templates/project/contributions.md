같은 목적의 커밋은 하나의 작업으로 묶습니다.

| 항목 | 내용 |
| --- | --- |
| 한 줄 요약 | [어떤 문제를 어떻게 바꿨는지] |
| 작업 기간 | [시작일 ~ 종료일 또는 진행 중] |
| 쓴 언어와 기술 | [이 작업에서 직접 쓴 기술] |
| 내가 맡은 일 | [책임지고 맡은 범위] |
| 함께한 작업 | [다른 담당자의 역할, 나눈 일] |
| 현재 상태 | [시작 전, 진행 중, 개발 완료, 확인 완료, 반영 완료, 보류] |
| 기록 기준일 | [YYYY-MM-DD] |

함께한 사람의 이름과 계정 이름은 적지 않습니다.

- 이전 상황: [기존 방식이나 서비스 상태]

- 영향: [누가 어떤 불편을 겪었는지]
- 바꾸려던 점: [이 작업으로 해결하려던 일]

### 어떻게 해결했는지

1. [문제를 확인한 방법]
2. [직접 고치거나 새로 만든 내용]
3. [다른 사람과 함께 정하거나 연결한 내용]

### 이 방법을 고른 이유

- 선택한 방법: [실제로 사용한 방법]
- 고른 이유: [상황에 맞았던 이유]
- 비교한 다른 방법: [다른 방법과 차이 또는 해당 없음]

### 결과와 확인

| 바꾸기 전 | 바꾼 후 | 확인 방법과 날짜 | 근거 |
| --- | --- | --- | --- |
| [이전 상태] | [달라진 점] | [확인 조건, 방법, 날짜] | [문서나 이슈 주소] |

수치를 적는 경우 같은 조건으로 비교한 값을 씁니다.
아직 확인하지 못했다면 결과를 예상해서 쓰지 않고 `확인 필요`로 적습니다.
