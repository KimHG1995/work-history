# 예약과 취소의 동시 요청 처리 개선

[공공 교육 플랫폼 작업 목록](README.md)으로 돌아갑니다.

예약과 취소에서 상태 변경과 잔여 인원 갱신을 하나의 처리로 묶었습니다.

## 기본 정보

| 항목 | 내용 |
| --- | --- |
| 작업 기간 | 2025-11 이후 근무 중 진행 |
| 맡은 범위 | 예약과 취소 서버 로직, DB 동시 접근 처리 개선 |
| 개발 상태 | 개발 완료 |
| 운영 상태 | 운영 중 |

## 배경과 과제

기존 예약 시스템에서는 예약 상태 변경과 잔여 인원 갱신이 하나의 트랜잭션으로 처리되지 않았습니다. 예약과 취소 요청이 동시에 발생하면 초과 예약이나 잔여 인원 불일치로 이어질 수 있어 두 데이터를 일관되게 변경할 필요가 있었습니다.

## 어떻게 해결했는지

- **원자적 처리:** 예약 가능 여부 확인, 예약 생성, 취소, 상태 변경과 잔여 인원 갱신을 하나의 트랜잭션으로 처리
- **동시성 제어:** MySQL 데이터 갱신 구간에 DB 잠금을 적용해 경쟁 요청 제어
- **예외 처리:** 예약 성공, 실패, 취소 상황에서 상태와 인원 수 변경이 함께 확정되거나 롤백되도록 구성

## 처리 흐름

```mermaid
flowchart TD
    request["예약 또는 취소 요청"] --> tx["트랜잭션 시작 및 DB 잠금 적용"]
    tx --> check["예약 가능 여부와 현재 상태 확인"]
    check --> update["예약 상태와 잔여 인원 변경"]
    update --> result{"처리 성공 여부"}
    result -->|성공| commit["트랜잭션 커밋"]
    result -->|실패 또는 예외| rollback["트랜잭션 롤백"]
```

## 결과와 현재 상태

예약, 취소의 상태 변경과 잔여 인원 갱신을 함께 처리하도록 운영에 반영했습니다. 동시 요청 시 두 값이 어긋날 위험을 줄인 것이 핵심입니다.
