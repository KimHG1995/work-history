## 왜 시작했는지

- 이전 방식: EC2에 직접 배포했다.
- 시작한 이유: 직접 배포하는 반복 작업을 줄이고 배포 절차를 일정하게 만들 필요가 있었다.

## 역할 분담

- 역할 분담: 선임 개발자가 Elastic Beanstalk 구성을 맡고, 본인은 해당 환경으로 배포하는 파이프라인을 작성했다.

## 기술 스택

| 구분 | 기술 |
| --- | --- |
| 배포 자동화 | Bitbucket Pipelines |
| 배포 환경 | AWS Elastic Beanstalk |

Elastic Beanstalk 환경은 선임 개발자가 구성했습니다.

## 어떻게 해결했는지

- 배포 환경: 개발과 운영 두 환경으로 나눴다.
- 실행 조건: 코드가 합쳐지면 파이프라인이 자동으로 실행되도록 했다.
- 처리 방법: 코드 빌드와 테스트를 거쳐 Elastic Beanstalk에 배포되도록 연결했다. 개발은 자동 배포하고 운영은 사람의 승인을 거쳐 배포했다.

## 결과와 현재 상태

- 결과: 수동 작업을 줄이고 같은 절차로 배포할 수 있게 했다.
- 서비스에 반영하고 실제 운영까지 진행했다.

## 배포 방식 변경

```mermaid
flowchart TD
    merge["코드 병합"] --> pipeline["Bitbucket Pipelines 자동 실행"]
    pipeline --> build["코드 빌드와 테스트"]
    build --> environment{"배포 환경"}
    environment -->|개발| dev["개발 환경에 배포"]
    environment -->|운영| verify["사람이 확인하고 운영 배포 승인"]
    verify --> prod["운영 환경에 배포"]
```
