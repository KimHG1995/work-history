# 이벤트 공통 코드 정리

[플랫폼 작업 목록](README.md)으로 돌아갑니다.

**작업 기간:** 2021-07 ~ 2024-01 근무 중 요청에 따라 진행.

## 시작한 이유와 문제

- 시작한 이유: 기업 고객 대상 광고와 매달 진행하는 재이용 유도 이벤트를 만들 때, 이벤트별로 코드를 따로 작성하고 있었다.
- 해결할 문제: 비슷한 이벤트에도 같은 코드를 반복해서 작성해야 했고, 처리 방식이 서로 달라질 수 있었다.

## 맡은 일과 역할 분담

- 요청과 기능 정리: 영업과 마케팅에서 재이용 유도 이벤트나 필요한 기능을 요청하면, 미팅을 통해 개발할 기능을 정리했다.
- 맡은 일: 관련 코드를 공통 모듈로 정리해 처리 방식을 맞추고, 비슷한 이벤트를 재사용 가능한 코드로 만들 수 있게 했다.
- 역할 분담: 디자이너와 내용을 논의하고, 본인은 백엔드 서버와 DB를 맡았다. 화면 개발은 각 이벤트의 프론트엔드 담당자가 진행했다.

## 기술 스택

Node.js, MongoDB, AWS Lambda, AWS EventBridge.

## 처리 방법

- 대상 기능: 광고를 통한 사용자 유입과 단계별 행동 확인, 푸시 발송, 지표 수집, 지표 알림.
- 처리 방법: Node.js와 MongoDB로 운영 API를 만들고, Lambda와 EventBridge로 예약 실행 흐름을 구성했다.

## 결과와 운영 상태

- 결과: 광고, 푸시, 지표 수집과 알림의 공통 코드를 재사용해 비슷한 이벤트를 반복해서 만들 수 있게 했다.
- 서비스에 반영하고 실제 운영까지 진행했다.
- 서비스 반영 날짜: 미확인.

## 이벤트 코드 정리 흐름

```mermaid
flowchart TD
    old["이벤트마다 광고, 푸시, 지표 코드를 따로 작성"] --> common["반복되는 기능을 공통 모듈로 정리"]
    common --> rules["모듈의 처리 방식을 일관되게 맞춤"]
    rules --> reuse["비슷한 이벤트에 공통 코드 재사용"]
    reuse --> event["기업 고객 광고와 매달 진행하는 재이용 유도 이벤트 구성"]
```

## 이벤트별 협업 흐름

```mermaid
flowchart TD
    request["영업과 마케팅의 이벤트 또는 기능 요청"] --> meeting["미팅으로 필요한 기능 정리"]
    meeting --> design["디자이너와 이벤트 내용 논의"]
    design --> assign["이벤트별 프론트엔드 담당 인력 배정"]
    assign --> backend["본인: 백엔드 서버와 DB 개발"]
    assign --> frontend["프론트엔드 담당자: 화면 개발"]
    backend --> operation["이벤트 운영"]
    frontend --> operation
```
